01What changed, in one page

The frontend reached its old state by accretion: 539 inline style blocks, 15 font sizes, 13 border radii, 41 stray hex colours, and two live palettes at once — a blue-black one in App.tsx and a neutral one in tokens.css, fighting over the same pixels. Roughly 98% of controls did not react to the cursor at all, because inline styles cannot express :hover. That accumulation is what read as "dated" — not any single bad screen.

The premium pass replaced accretion with a system:

LayerBeforeAfter
Colour41 stray hex values, two competing palettesOne token file; a token linter fails the build on any hex outside it
Type15 ad-hoc font sizes5-step scale + display role; Geist / Geist Mono, tabular numerals everywhere
DepthFlat panels, no elevation logic3-step pure-black shadow ramp + translucent glass chrome
Interaction~98% of controls inertOne Button primitive; hover/focus/press defined once
Welcome screenPlain flat cardHero with brand mark, feature strip, inverted-ink CTA, ambient glow
GuardrailsNonelint:tokens + lint:tdz run inside npm run build
The governing rule: chrome and text are dead neutral (R = G = B). Machine judgements are cold or absent. Warm colour — the grease-pencil orange — appears only where the photographer put it: his stars, his selects, his rejects. A tool whose job is judging light may not tint its own chrome.

02The token system — single source of truth

src/theme/tokens.css is the only file permitted to contain a raw hex or raw px size. Tailwind's config maps every utility (bg-surface, text-ink-2, rounded-md…) to a custom property, so runtime values flow through the same names — and the linter keeps it that way mechanically.

03The welcome hero — anatomy of the redesign

The welcome screen is the app's first impression and its only photograph-free surface — which makes it the one place the warm mark colour may breathe as ambience.

Before
Flat grey card floating on flat black. Version chip, one outline button, no hierarchy beyond size. Nothing reacted to the cursor.
After
Elev-3 card with top-light hairline edge, aperture-mark brand row, display headline with a mark-coloured full stop, three-verb feature strip between hairlines, inverted-ink CTA, resume strip on ground, two soft ambient glows behind.

Live render, localhost:5173 — headless-Chrome capture after the ink-CTA pass.

Design decisions worth naming

  • The full stop is the signature. FrameGrade. — small, confident, and the only warm glyph on the entire stage.
  • Three verbs, not three paragraphs. Graded / Culled / Sequenced — the product described in six words of body copy, separated by hairlines rather than cards-in-cards.
  • Ambient glows stay hue-safe. A --mark-dim radial (15% tint, 48px blur) over a raised-grey radial — present depth, zero contamination, and always behind the card, never behind photographs.
  • The resume strip is honest chrome. Ground-coloured, hairline-separated; session continuity ("Pick up where you left off?") is a first-class citizen of the layout, not a toast.
  • Entrance is one motion. A single dialogIn rise-and-settle on the shared 220ms curve — no staggered children, no bounce.

04The button system — and the new ink variant

One primitive, src/components/ui/Button.tsx, owns hover, focus, press and disabled states once. Deliberately absent: an accent-coloured primary. Emphasis is carried by luminance and border weight, never hue.

VariantRecipeUsed for
defaultTransparent + line-strong border, ink-2 labelToolbar actions
quietNo border, ink-3 labelDense clusters where borders would add noise
solidRaised fill + line-strong borderEmphasised actions (header "Grade")
ink ★ newbg-ink text-well — inverted, full-luminance white fillThe ONE primary action on a screen (hero "Open folder")
dangerNeutral until hover, then alarm-crit border/labelDestructive actions
// The 2026 addition — strongest step the chrome may take, still strictly neutral.
ink: 'bg-ink border border-ink text-well hover:opacity-90 active:opacity-85',

Why inverted ink instead of a coloured primary: on a dark, neutral tool, a white button is the highest-contrast statement available — the Linear/Vercel pattern — and it cannot leak warmth into photo judgement. Hover dims the fill (opacity) rather than swapping tokens, so the inversion survives the cursor; active:scale(.98) gives press feedback without layout cost.

05Guardrails — how this stays premium

  • npm run lint:tokens — fails the build on any raw hex or bare fontSize: in managed code. Legacy literals are baselined at 0. This is the point: only a mechanical check keeps 41 stray hexes from drifting back.
  • npm run lint:tdz — temporal-dead-zone check; the token refactor moved declarations, and this class of bug is now mechanical to catch.
  • Keyframes live in index.css, not the Tailwind config — Tailwind only emits @keyframes it can see referenced by utilities in source, so config-only keyframes silently killed 11 spinners and every skeleton. Plain-CSS declaration makes emission unconditional; the linter enforces the pairing.
  • Reduced-motion policy — opacity fades (they carry the Weak/reject meaning) survive; every transform is dropped.
  • Focus is neutral, two-ring — light outer + dark inset, so the indicator survives both on chrome and on top of a blown highlight in a photograph.
  • Scrollbars and range inputs are themed — native OS controls read as foreign objects in a custom dark UI, so they're rebuilt on the token scale.
