# FrameGrade — runtime dependencies.
#
# Everything is pinned. This file used to leave 26 of 28 packages floating, so
# two installs a week apart produced different environments, and a transformers
# release could pull a torch that overwrote the CUDA build.
#
# ── Installed by the installer, NOT by this file ─────────────────────────────
# Three packages need a build chosen from the machine, so Setup.ps1 installs
# them BEFORE running this file (pip then sees them satisfied):
#
#   torch==2.5.1 / torchvision==0.20.1
#       --index-url https://download.pytorch.org/whl/cu121   (NVIDIA present)
#       --index-url https://download.pytorch.org/whl/cpu     (otherwise)
#       Listing torch here would let pip overwrite the CUDA build with a CPU wheel.
#
#   onnxruntime-gpu==1.22.0   (NVIDIA present)  /  onnxruntime==1.22.0 (otherwise)
#       ONNX is the default image encoder on the Pro tier. Installing the CPU
#       wheel on a GPU machine is NOT harmless: run_profile.onnx_enabled() still
#       returns True, ORT silently falls back to CPUExecutionProvider, and the
#       encoder drops from ~1.2 s/img to 11-14 s/img with no error.
#       The CPU wheel below is the floor so a bare `pip install -r` still works.
#
#   llama-cpp-python==0.3.23
#       --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/<cpu|cu121>
#       The PyPI sdist builds from source and needs CMake + MSVC Build Tools,
#       which a clean Windows machine does not have. It is a hard install failure,
#       not a warning. This is the local GGUF runtime — jury_engine and
#       critique_engine both load through it.
